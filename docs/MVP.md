# 《电子产品发展国》MVP 功能列表

> 状态：**草案进行中（v0.7 补产品 DIY 与展示）** · 对齐轻松开罗风 · 2026-11-01  
> 关联：[GAME_DESIGN.md](./GAME_DESIGN.md) · [DISCUSSION.md](./DISCUSSION.md) · [README](../README.md)

---

## 1. MVP 成功标准（一句话）

玩家能在 **20～40 分钟**内，不查攻略地走完一整环：

**企划 → 研发（少槽加点）→ 供应链选项（供应商档 + 至少一张事件）→ 发布会 → 卖一个月（媒体分 + 销量反馈）→ 规划下一代（可开二代企划）。**

MVP 以 **3 年短局**（约 4～6 代）承载这一环和后续两三代；第二、三代要有**新的决策**（配比、档期、期望线），而不是重复第一代。

失败（破产 / 口碑崩）应能 **快速重开**，且能说出「这局错在三角权衡 / 事件选项 / 发布会」之一——而不是怪隐藏公式。

## 2. Must-have（必须进 MVP）

每条：**一句话功能** + **为何必须**。

### 2.1 开局

| # | 功能 | 为何必须 |
|---|------|----------|
| M1 | **新建公司**：输入/随机公司名 + 选一个起点模板（MVP 可先做「车库创业」一种）。 | 给身份与初始现金/人手，立刻进入开罗式「开一局」。 |
| M2 | **品类锁定为手机（第一环）**：首款只能做手机；文案说明配件留二期。 | 削内容面，保证 20～40 分钟能闭环。 |
| M3 | **简短目标提示**：本季目标一句话（如「发出首款并别亏光」）。 | 降低迷茫，贴短循环。 |

### 2.2 人才

| # | 功能 | 为何必须 |
|---|------|----------|
| M4 | **岗位花名册 4～6 人**：工业设计、硬件 PM、影像、系统、供应链、公关等（可缺席招聘）。 | 发展国手感的核心是「人」；无岗则研发无梗。 |
| M5 | **招聘 / 分派**：花钱招人；把人拖到研发槽或「发布会准备」。 | 让玩家做组合，而不是纯点数值。 |
| M6 | **一句性格/特长梗** + 星级：影响槽位速度或事件选项质量（规则写明）。 | 可读反馈；有梗才像开罗。 |

### 2.3 企划

| # | 功能 | 为何必须 |
|---|------|----------|
| M7 | **产品企划屏**：选定位（旗舰/主流/极简/专业）、2～3 个卖点标签、售价带。 | 没有企划就没有「这一代在赌什么」。 |
| M8 | **三角预览**：企划结束时显示体验上限预期 / 成本压力 / 预计工期的可读条。 | 落实已锁定的轻量三角权衡。 |
| M9 | **生态开关（可极简）**：本代「绑上代生态 / 不绑」二选一（首代可灰掉）。 | 为下一代与蚕食留钩子，又不做复杂生态模拟。 |

### 2.4 研发槽

| # | 功能 | 为何必须 |
|---|------|----------|
| M10 | **≤5 个模块槽**：性能、屏幕与外观、影像、续航与稳定、系统与生态。 | 少数清晰槽；玩家不记七七八八。 |
| M11 | **月度回合：分配人力点数到槽**；推进槽位进度条与总工期条。 | 主循环操作，对标发展国「丢骰子/加点」的节奏。 |
| M12 | **槽位即时短评**（「更流畅了」「外形有点信仰」）。 | 可读反馈，避免纯数字。 |
| M12a | **定位理想配比 + 匹配度**：体验分 = 研发量 × 匹配度；发布后给配比雷达与逐槽「多了/少了/刚好」。 | 核心乐趣支点 A；让研发分配成为真决策（[GAME_DESIGN §3.4.2](./GAME_DESIGN.md)）。 |
| M12b | **卖点承诺**：卖点绑定槽位，不达标「货不对板」扣分。 | 企划与研发联动，卖点不再是装饰。 |
| M12c | **企划笔记**：高匹配后记录该定位的理想配比，推荐会采用。 | 学会的东西可见，休闲玩家也有成长感。 |

### 2.5 供应链轻系统

| # | 功能 | 为何必须 |
|---|------|----------|
| M13 | **供应商三档选一**：便宜不稳 / 均衡 / 贵但稳（影响成本条与事件权重）。 | 电子题材差异点，但仍是「选项」不是 ERP。 |
| M14 | **研发期事件卡**：池子 6～8 张（至少含缺芯、良率、泄露）；每卡 2～3 选项（加钱/延期/降规格/赌），代价随现金、档期变化。 | 供应链戏剧性；轻松开罗的「糟了！」瞬间，且没有万能选项。 |
| M14a | **档期 + 年度趋势 + 1 家虚构竞品**：企划选目标发售月；延期选项显示错过档期的后果；竞品提前放传闻。 | 支点 B；让「时间」成为真代价（§3.4.4）。 |
| M15 | **发布前备货三档**：保守 / 正常 / 激进 → 首月缺货或积压的**短句+小额现金**；剩余库存进入长尾月份继续卖并扣仓储费。 | 有库存味，无精细算法。 |

### 2.5b 产品 DIY 与展示（[GAME_DESIGN §4.8](./GAME_DESIGN.md)）

| # | 功能 | 为何必须 |
|---|------|----------|
| M15a | **配置台**：芯片 / 屏幕 / 主摄 / 电池 / 材质 / 尺寸 各 3 档（虚构命名），决定槽位上限、成本、厚度/重量；实时读数含虚构跑分。 | 硬件取舍看得见，接入匹配解谜。 |
| M15b | **外观台**：机身尺寸 × 圆角、屏幕形态、镜头布局预设、色板 + 自定义主色 + 双色、机型名；一键随机 / 沿用上代。 | 玩家表达欲；60～90 秒内完成。 |
| M15c | **像素化 3D 预览**：three.js 参数化机型，可拖拽旋转，按需加载。 | 「欣赏自己的产品」的基础。 |
| M15d | **外观计分**：材质 × 定位、趋势命中、设计语言连贯、厚重超标扣分。 | 外观有意义但不评判审美。 |
| M15e | **发布会 360° 揭幕** + **历代机型馆**展示墙。 | 爽点与收集感。 |

### 2.6 发布会

| # | 功能 | 为何必须 |
|---|------|----------|
| M16 | **短发布会关卡**：会前 1～2 准备选项 + 会中 2～4 节点选项（彩蛋/参数/Demo 稳不稳）；风格与卖点匹配，翻车率由产品稳定度决定。 | 核心爽点关卡；卖点「发布会要爽要快」，且没有固定最优解。 |
| M17 | **当场结算屏**：媒体分、用户期待、一句头条文案（有梗）；**显示期望线**。 | 立刻爽；分数高低原因可读（§3.4.5）。 |

### 2.7 评价与销售

| # | 功能 | 为何必须 |
|---|------|----------|
| M18 | **首月销量结算 + 长尾**：大数字销量、收入、备货短评；旧款在下一代研发期间继续衰减在售，新品上市触发轻蚕食三选一。 | 闭环「卖一个月」，并让世代之间连起来（§3.4.7）。 |
| M18a | **价格 × 定位联动**：价带偏离定位扣用户分；需求随价格下降，无高价碾压。 | 修掉「最高价带永远最赚」（§3.4.3）。 |
| M19 | **口碑 / 信仰值轻量变化**：用大字或箭头表示，规则一句话说明。 | 给下一代动机，不做复杂舆情模拟。 |

### 2.8 公司月报

| # | 功能 | 为何必须 |
|---|------|----------|
| M20 | **月末一页月报**：现金、盈亏、在研进度、本月事件回顾一行。 | 公司感与可读性；方便决定下月人力。 |
| M21 | **破产 / 通关提示**：现金≤0 可重开；发出并卖过一代可「规划下一代」。 | 失败快重来；满足成功标准最后一环。 |
| M21a | **轻成长**：技术点升级槽位上限、员工升星、办公室扩建（+人力点）。 | 追上期望线的手段，给长期目标（§3.4.6）。 |
| M21b | **3 年短局结算**：第 36 个月结算并给结局称号。 | 给一局明确终点。 |
| M21c | **推荐 = 稳但平庸**：全程点推荐不破产，但媒体分到不了 80+。 | 保留少点击，又不让推荐替玩家玩（§3.4.9）。 |

### 2.9 存档

| # | 功能 | 为何必须 |
|---|------|----------|
| M22 | **本地单存档或 1～3 槽存读**（自动存月边界即可）。 | 20～40 分钟也可能中断；无存档无法试玩讨论。 |
| M23 | **新建游戏确认覆盖**。 | 防误触；服务快速重开。 |

## 3. Nice-to-have（二期，不挡 MVP 验收）

- 第二起点（小品牌翻身 / 已有产品线）与教程机独立关  
- 配件品类（耳机/表）与更明显的自相蚕食策略菜单  
- 发布会独立小关卡加长、KOL 邀请组合  
- 分享「我的发布会结果卡」图  
- 更多事件卡主题（认证、关税惊吓、挖角）  
- 像素办公室与 UI 美术精修  
- 服务订阅开关补毛利、多语言 i18n  
- 结局图鉴与挑战模式（情报更噪等）  
- 10 年正式局、多家竞品、员工疲劳/挖角  
- 研发中样机逐步成型（线框 → 素模 → 成品）  
- 外观彩蛋件（透明后盖、背部副屏、呼吸灯）与相关话题事件  
- 发布会结果 / 产品名片分享卡

## 4. Explicitly out of scope（MVP 禁止做）

- 精细 BOM 行项目、多级库存、物流/关税 ERP  
- 真实芯片制程节点树、真实商标/写实机模  
- 自由捏模 / 雕刻、导入图片或模型、毫米级参数输入、内部堆叠 / PCB、写实 PBR 渲染  
- 完整财报、税务、实时股价硬核盘  
- 开放世界园区、联机对战、社区排行  
- 自由文本文书/参数数据库、重度数值模拟器  
- 五大门类同时开做

## 5. 建议垂直切片顺序（先做 3 个可玩里程碑）

| 里程碑 | 可玩内容 | 验证什么 |
|--------|----------|----------|
| **V1 灰盒环** | 无人才或假人：企划 → 3 槽研发点点点 → **跳过**供应链 → **假**发布会结算 → 假销量 → 能点「下一代」 | 月度循环与 20～40 分钟节奏是否成立 |
| **V2 开罗味** | 加上招聘分派、≤5 槽短评、供应商三档 + 2～3 张事件卡、真发布会选项 | 人/事件/发布会是否「有梗且爽」 |
| **V3 MVP 候选** | 备货三档、月报、存档、破产/重开、完整成功标准一句话验收 | 可给外部朋友试玩的垂直切片 |
| **V4 决策深度** | 理想配比 + 匹配度 + 卖点承诺、价格联动、档期/趋势/1 竞品、期望线、长尾销量、轻成长、3 年短局 | 第二、三代是否有新决策；跑一遍 GAME_DESIGN §3.4.11 数值清单 |
| **V5 产品 DIY** | 配置台、外观台、像素化 3D 预览、外观计分、发布会 360° 揭幕、机型馆 | 玩家是否愿意花时间欣赏/调自己的机型；部件取舍是否看得懂 |

之后才扩品类、美术、二期列表。

## 6. 验收 Checklist

- [ ] 新玩家无讲解可在 **40 分钟内**走完成功标准全环（计时）  
- [ ] 存在 **企划 / 研发槽 / 供应商或事件 / 发布会 / 销量 / 下一代** 六类界面或弹层  
- [ ] 研发槽 **≤5**；人才岗 **≥4** 可招募或预置  
- [ ] 供应链 **无** BOM 表、**无**多级库存 UI  
- [ ] 发布会结束有 **媒体分大字**；销售有 **首月销量大数字**  
- [ ] 月报能看到现金与进度；现金耗尽能重开  
- [ ] 存档可恢复到当月；中文文案完整可玩  
- [ ] 试玩者能口头指出本局主要失误类型（权衡 / 配比 / 档期 / 事件 / 发布会）  
- [ ] GAME_DESIGN §3.4.11 数值验证清单全部通过  
- [ ] 全程点推荐：不破产，媒体分 < 80  
- [ ] 外观台 90 秒内可完成；「沿用上代」一键可用  
- [ ] 换电池 / 主摄档位，3D 上能看出厚度 / 镜头模组变化  
- [ ] 中端手机浏览器上 3D 预览流畅，首屏不因 three.js 变慢

## 7. Must 摘要（给快速对齐用）

1. 开局：命名 + 车库起点 + 只做手机  
2. 人才：4～6 岗招聘分派，有星级与一句梗  
3. 企划：定位/卖点/售价 + 三角预览  
4. 研发：≤5 槽月度人力分配 + 短评；**理想配比 + 匹配度 + 卖点承诺**  
5. 供应链：三档供应商 + 事件卡 + 备货三档  
6. 发布会：短选项 → 媒体分当场弹  
7. 销售/月报：首月销量与月末一页；能开下一代  
8. 存档与快速重开  
9. 档期 / 趋势 / 1 家竞品 + 期望线 + 长尾销量 + 轻成长 + 3 年短局  
10. 推荐 = 稳但平庸  
11. 产品 DIY：配置台 + 外观台 + 像素化 3D + 发布会揭幕 + 机型馆
